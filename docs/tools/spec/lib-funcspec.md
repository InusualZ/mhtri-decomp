# `lib/funcspec` - Which function the mwcc debugger dumps

## Purpose

Turns the text a lane types for `mwcc_debugger.py` (`FUNC` or `--symbol FUNC`) into one `Selector`, and answers whether
the compiler's current function is that selector. Without it the debugger compared a plain name only: `create` hit another
class's function, and a mangled name never matched and ran the compile to its end (`gdb.MemoryError` at 0x2).

## Users

`tools/mwcc-debugger/mwcc_debugger.py` (generated by `make_port.py`: the launcher parses, the gdb side matches).

## Public API

* `parse(text, rows=(), size=0) -> Selector`: `text` is a mangled name, `Class::method` (`A::~A` = `__dt`, `A::A` = `__ct`),
  an address (`0x8009792C` / `8009792C`) or a plain name. `rows` are the map's `.text` function rows `(symbol, address, size)`
  (`function_rows(symbols_path)`); with them an address names its row, `Class::method` (or a plain name with `size`) is
  upgraded to the one row it identifies, and a plain name that several rows share gets a note. `SelectorError` for no row,
  no function of that size, or more than one candidate (listed).
* `Selector`: `name` (source identifier), `scope` (owner chain, outermost first), `exact` (the scope is whole: a mangled name),
  `mangled`, `size`, `address`, `notes`; `label` (what a dump is stamped with: the link name when known), `extract_name`
  (what `lib.cextract` is asked for), `to_dict`/`from_dict` (the JSON hop into gdb), `matches(name, linkname, scope)`:
  source name equal; a cached link name decides when both sides have one; else `scope` equal (exact) or ending in the
  selector's (`Class::method`); `scope` None (a build whose record hides it) matches by name.
* `scope_chain(read_u32, read_string, node)`: the owner chain of the compiler's scope record (`+0x00` parent, `+0x04` name
  node, text at `+0x0A`), bounded; pure given the two readers.
* `function_rows(symbols_path)`: the map's `.text` functions, `[]` when the file is missing.

## Invariants and rules

* The owner-scope parse of a mangled name is `lib.names.split_member` (the same walk as `owner_stem`); this module holds no
  second copy of the mangling grammar.
* A resolved row becomes its `Selector` through `_row_selector`, never by re-parsing the row's name: a plain (C-linkage) row
  selected by `--size` or an address used to recurse forever (`regsim run --size N`).
* A plain name keeps its old meaning (the first function of that name); the ambiguity is reported, never silently resolved.
* The scope record layout (`+0x08` of the Wii/1.3 object record) was read from the live compiler (2026-11-12:
  `ResUserDataAc`, `nw4r::g3d::ICalcWorldCallback`, the global scope with no name and no parent); the GC rows do not expose it.

## Lib dependencies

names, project (`SymbolMap`).

## Test contract

Tier: fixture - `tools/tests/mwcc-debugger/test_funcspec.py` (44 checks): every selector form, the ambiguity and no-row
refusals, `matches` on class chains and cached link names, the scope walk (parent order, global scope skipped, cycle
bound) and the map rows; `test_selector_cli` in `test_mwcc_debugger.py` drives the launcher's refusals without a compiler.

## Known gaps

* Overloads of one class sharing a name are told apart only by the link name, which the compiler caches for some functions
  only; otherwise the first of them is dumped (the selector's `size` is not compared with the generated code).
