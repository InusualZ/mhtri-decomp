## 2. Method (one tool, no per-unit judgement)

For every data section the unowned symbols between two owned ranges form a **run**; its **chain** is the text-having units in link order from the
owner before the run to the owner after it (a data-only owner between makes its neighbour unable to extend, so it is excluded). A monotone dynamic
program assigns the symbols to the chain minimising the violated evidence; a symbol is **decided** when every optimal assignment gives it one unit.

* **Strong evidence**: the units whose text reads the symbol (`splitcheck.Ctx` decode; pool literals by loads only; a `jumptable_` by its branch
  targets when no reader decodes). **Derived evidence** (weight 1, never overrides a strong row): the units whose functions a table's words point at,
  and the units of the data symbols it points to or is pointed from (pointer graph, two rounds, across sections; owned symbols count by their owner).
* **Link order** is the only other input: units link in text order in every section, so a stretch of unread symbols between two anchors of one unit is
  that unit's (signal 8), and between anchors of two units it is ambiguous over the interval.
* **Interleave**: a strong row the optimum violates is a contradiction; static ones (`jumptable_`, `scope:local`) and clusters of three or more between
  adjacent data-bearing units mean the two units' data alternates. Not attached, listed with both candidates.
* **Settling**: the decided attachments are rendered and every invariant run; an attachment that makes a unit fail one the phase-1 candidate does not
  is blocked (`unowned_data` kind `multi-tu` + a `guess` attachment) and the loop repeats. 75 new FAIL items in round 0, 0 in round 1; 6 blocked in the
  window (69 over all windows, the rest are other lanes' and are not in these files).

Signals of the brief, as labelled in `signals`: 1 `reader` / `readers` (a global read by several units); 3 `pool-order` (`.sdata2` literal, sole load
reader, link order monotone, one literal at one address per unit); 4 `vtable-store`; 5 `local-static`; 6 `jumptable`; 7 `file-string`; 8 `forced`
(link order between anchors); plus the derived `code-pointers` and `pointer-graph`. Signal 2 (the `D* S* V* s*` seam grammar) decides nothing on its own
here (only 6 ambiguous `.data` symbols are left); it is the reason a V->S gap is not a failure inside a range (section 8).

## 4. Findings the data makes about the text cuts (phase 3 input)

1. **Data interleave, three clusters** (`unowned_data` kind `interleave`; 485 symbols). A TU's data is contiguous, so a unit whose data lies on both
   sides of another's (or whose static jump tables follow a later unit's data) is the same TU or reads data that TU defines.
   * `ef/fn_800FD864` + `fn_800FE978` + `eft004` (0x8059B9A8..0x8059C521): fn_800FD864's 11 jump tables (0x8059C19C..0x8059C364, read only by it) and
     fn_800FE978's three lie after eft004's data and before eft004's own table (0x8059C45C) and its inline-tail strings (`emitter.h`,
     `res_emitter_ac.h`): the grammar of one TU (definitions, then the S group in function order). **Merge test passes**: `phase2-p2b-merge-c.json`
     merges the three (cut 0x800FE978 and 0x800FF8D4 removed) and attaches the 79 symbols; every invariant count stays at the phase-1 candidate's (pool
     63, ctors 0, jumptable 1, data-order 0) and the merged unit PASSes everything. Apply it **with** `phase2-p2b.json` (its attachments to the three
     absorbed units land on the merged one, `splitcheck` resolves `absorbs`); the file holds the merge unit and the one new attachment, and
     `dataattach_b.py --ignore-phase2 --proposal <phase 1 files> --proposal phase2-p2b-merge-c.json` re-derives the whole window on the merged candidate.
   * `sound/quest_snd` + `fn_800EF7D8` (0x805980A8..0x8059B16C, 375 symbols; eight symbols read only by quest_snd lie inside fn_800EF7D8's tables) and
     `ef/eft001` + `eft002` (0x8059B5F8..0x8059B9A8, 31 symbols; eft002's tables lie between eft001's): **the merge fails**: the merged unit reads one
     `.sdata2` value at two addresses (quest_snd at 0x80796598, eft001_fx at 0x80796644), which is two TUs. Both hold, so the alternatives are extern data
     defined in the neighbour's TU or a data-only TU between them; left open with both candidates.
2. **Micro unit `enemy/fn_801B4348` (0x801B4348..0x801B4458)**: `em034_prog_tbl` (0x805B17A8) lists functions of `fn_801B4458` only, yet lies before

## 8. Tool and checker changes (six commits: `tools/splitcheck` x4, `tools/dataattach_b` x2)

* **Format** (`splitcheck.py`, additive): top-level `attach` / `unowned_data` (+ `lane`, `window`), a phase-2 file may have no `units`;
  `docs/splits-program.md` documents them. `render` applies non-`guess` attachments (a provisional by-reader range is replaced, any other overlap is a
  `lint:`), resolves a name a `guess` merge folded away and a name a unit `absorbs`. Selftest 78 -> 96.
* **`data-order`**: a strong V->S gap failed any unit whose range held the first string; it now fails only a range that also holds the later vtable (a
  range that ends inside the gap ends at the boundary). Baseline FAIL 3 -> 0 (`nw_resource`, `NetworkSessionManager`, `fn_8041A87C`: all three end
  inside their gap), phase-1 candidate 3 -> 0.
* **`pool`**: first-use order is judged per section; a unit claiming `.sdata` strings and `.sdata2` literals was compared across the two pools (a
  false FAIL on every unit holding both, including mhchar).
* `check_jumptable` named the first foreign reader out of a set, so the finding (and any file quoting it) changed between runs; it is name-ordered now and
  the main file is byte-identical across runs and hash seeds.
* `dataattach_b.py` (new, 15 checks): the decider, the settle loop, `--unit` explain. Phase-1 candidate output is byte-identical before and after all
  changes (`cmp` of `--emit-splits`).

## 9. Tool gaps and residuals

* The `datagap` classes (`pool-synth`, `claim-exposed`) need built target objects; a worktree without `build/` cannot compute them.
* `callers.py` and the decode count an interior read of a large map symbol as a read of the symbol (`jumptable_8059FE90`); the jumptable and
  local-static invariants inherit that. A map pass that splits such symbols per table would clear item 4 of section 4.
* The zigzag rule is the only data-order rule that fires on single-slot vtables; it has no retail validation (docs/data-order-seams.md section 3).
* Six `unread` items hold symbols nothing decodes a read of (6.5 KB of `.bss`); only a link-order neighbour can place them.
* The merge scenario is one of three interleave clusters; the other two are contradicted by the pool and stay open (section 4.1).
