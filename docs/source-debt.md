# Source debt inventory

Where the source carries the same type or declaration more than once, why, and what unifying needs.
Generated by `build/tmp/cleanup/dupes.py`-style scans (struct/class bodies at line start across `src/` and
`include/`); 61 type names are defined in more than one file. Nothing here is a behaviour change: every
item is a rule 1 (one shared header) debt for a decompiler lane that already has the unit open.

include does not clash (the old band headers `unsplit/enemy.h` and `enemy/fn_80165FC8.h` declare helpers
with signatures that disagree with the named ones - the em008/em010 sources hide `em_mot_set` and friends
with macros for that reason).

## Effect heap views

`EmCharBase` (`src/enemy/fn_80138074.c`), `_EFT_S8` (`src/ef/fn_800FD718.c`), `_EFT_HEAP` / `_EFT_HEAP_WORK`
(`src/ef/fn_80119C44.c`) are each defined in a single source only; they are the private views the unit's
own functions were matched against. Moving them to a header is a rule 1 step once a second unit needs them
(the declaration moves the second time it is needed, never the first).

## Per-source namespaces `view_fn_*`

`view_fn_802D0F34` (`src/ai/ai_npc.cpp:3025`), `view_fn_802B2AA0` (`src/camera/camera_main.cpp:527`,
`src/stage/stg_w.cpp:718`), `view_fn_802E4978` / `view_fn_802EBED8` (`src/hud/cockpit_quest.cpp:401`, `:3195`):
a source wraps the include of a header whose types clash with the unit's own (`_mh_ivec2_`, `_SPR_DATA_`,
`_HIT_W`, `_PLW` are each defined differently by `ai/fn_802D0F34.h`, `stage/fn_802B2AA0.h`,
`menu/fn_802E4978.h`, `hud/cockpit_quest_marker.h`), so the header's declarations land in a namespace and
the two views never meet. The headers are named for units that were folded into the unit that includes them
(their `src/*/fn_<addr>.cpp` no longer exists). Unifying needs the clashing type pairs reconciled (offsets
and field names from the function that reads each field), then the namespace wrapper and the duplicate
type go away.

## Function-pointer cast views in the enemy programs

`src/enemy/em*_prog.cpp` carry 224 `<name>_viewN` macros (for example `rotMatrixZ_view1`,
`fn_8015D934_view1`): a retyped function pointer used because the unit's own header declares the callee
with a signature that clashes with the one the call site needs. They exist because of the stale
enemy band declarations; the retype disappears once the callee has a single named declaration (see the
`unsplit/enemy.h` residual below).

## Band headers (`include/unsplit/*.h`)

Re-measured 2026-10-04 (`stylelint.py --budget --headers`, the r2 column summed over `include/unsplit/*.h`): the band
headers still carry **913** declarations of a symbol a registered unit owns (943 after this batch's move). Largest:

compile time, 7 sat in an owner header the tool could not extend safely, 6 were manglings (rule 9).
