# 303. GC/3.0a5.2 rematerialises a multiply-used zero per block where GC/3.0a3..3.0a5 hold it in a saved register across calls

**Problem.** `sdp_init` (BTE) clears a control block, stores a few constants, makes two calls, then stores a zero
trace level and three NULL callbacks. Retail: `li r29,0` scheduled among the first call's arguments, kept across
both calls, and `stb r29`/`stw r29` x3 at the end (416 B, r29-r31 saved). Under GC/3.0a5.2 the same plain source
gives one `li r0,0` in the store block and no r29 (408 B). A zero local under a scoped `opt_propagation off`
brings the `li r29,0` back but, as a named local, it is numbered below the two address temporaries and has 28
interference neighbours (one short of the 29-colour stall), so it is pushed in the first simplify scan, `&sdp_cb`
drops to 28 and is pushed too, and only the string base stalls: string r31 / `&sdp_cb` r30, the reverse of retail
(ideas 243/244). A zero defined before the memset stalls (29 neighbours) and colours right, but its `li` lands in
the first block. A u8 local keeps the colouring and rematerialises the pointer stores (`li r0,0`, 420 B). 46
spellings and the regsim replay (`fold r35 into zero` is the only exact plan, and no C source folds a `lis` hi-part
into a zero) all stop there.

**Why it happens.** GC/3.0a5.2's constant handling differs from the earlier GC/3.0a* builds: with the plain source,
GC/3.0a3, 3.0a3.2, 3.0a3.3, 3.0a3.4, 3.0a3p1 and 3.0a5 all create the zero once, in the second block, as a
temporary numbered above the address temporaries, and keep it in r29 across the calls - the retail object byte for
byte. Idea 81's "compilers inside one family are usually identical" does not hold between 3.0a5 and 3.0a5.2 for
this shape; every other row of the unit is identical under both.

**How to work it.** When a GC/3.0a5.2 unit's only residual is a multiply-used constant that retail keeps in a saved
register across calls (or any saved-register swap that no source shape moves), compile the plain source under
GC/3.0a5 and the other 3.0a* builds before writing locals or pragmas: a per-object `mw_version="GC/3.0a5"` is the
lever, and it is evidence-backed by the instruction diff (rule 3). Keep the source as the vendor wrote it.

**Result.** `BTE/sdp_main` (`cflags_nw4r`): `sdp_init` 98.894 % (420 B for 416 B, one `li r0,0` inserted and three
`stw r0` for `stw r29`) -> 100 % with the plain BTE source and `mw_version="GC/3.0a5"` (the local and the pragma
removed); unit 10/11 -> 11/11 rows, 99.84268 -> 100.0; flipcheck READY; trial flip `ninja build/RMHE08/ok` 0 FAILED,
`main.dol: OK`, sha1 bf4850739478caaedfe675949eb7c28595a7fde9 with `build/RMHE08/src/BTE/sdp_main.o` linked.

**Example.**

```
configure.py:  Object(NonMatching, "BTE/sdp_main.c", mw_version="GC/3.0a5", cflags=cflags_nw4r),

    sdp_cb.trace_level = 0;                      /* retail: stb r29 - the zero materialised before the first call */
    sdp_cb.reg_info.pL2CA_ConnectPnd_Cb = NULL;  /* stw r29; GC/3.0a5.2 emits li r0,0 + stw r0 here instead */
```
