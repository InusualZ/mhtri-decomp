# Verify a unit, function or symbol actually matches

"Matches" has exactly one meaning in this repo: our `src/**` build reproduces the original object
byte-for-byte in code, data, relocations and section layout. Anything short of that is **not a match** and
must be reported as such, with numbers.

## 1. Decide what you are verifying

| Target | Command |
| --- | --- |
| whole unit | `build/tools/objdiff-cli.exe diff -p . -u <unit> --format json -o <out>.json` |
| one function in a unit | same, plus the **positional** symbol: `… --format json -o <out>.json <symbol>` |
| a symbol whose names differ on each side | add `--selecting-left <target_name> --selecting-right <our_name>`, or map with `-m <target>=<base>` |
| two arbitrary object files, no project/`objdiff.json` | `build/tools/objdiff-cli.exe diff -1 <target.o> -2 <base.o> --format json -o <out>.json [<symbol>]` |

The positional `<symbol>` only picks the *focused* symbol (it is what the interactive/GUI view expands); the
JSON still lists every symbol, so per-symbol numbers always come from the full unit diff. `-1/-2` is the
escape hatch for objects that are not in `objdiff.json` at all.

**Finding the unit for a symbol** (do not print `symbols.txt` — rule 7):

```sh
grep -n "^<symbol> = " config/RMHE08/symbols.txt     # -> section:address; // type:function size:0x…
grep -n -B2 -A20 "<Lib>/<file>" config/RMHE08/splits.txt   # which ranges that TU owns
```

Unit naming in `objdiff.json` is `<lib>/<file>` with no extension, e.g. `main/Camellia/camellia` (grep
`objdiff.json` for the file name, or for the address, when unsure). `<lib>` is the `config.libs` entry name,
usually prefixed `main/`.

## 2. Ground truth

| Path | What it is |
| --- | --- |
| `build/RMHE08/obj/<Dir>/<file>.o` | **target** — the original object split out of the DOL |
| `build/RMHE08/src/<Dir>/<file>.o` | **candidate** — our compiled object |
| `objdiff.json` | unit list generated by `configure.py` (target/base paths + per-unit flags/compiler) |
| `config/RMHE08/splits.txt` | the address ranges each target object was split from — truth for target sizes |
| `config/RMHE08/symbols.txt` | symbol → `section:address`, type and size (grep/slice only) |

Authority ranking: **per-symbol `match_percent` → unit `fuzzy_match_percent` → raw section bytes & sizes**.
Nothing else. `complete_code_percent` is worthless (it has read `100.0` for a unit that was 1.49 % matched)
and `Object(Matching, …)` in `configure.py` is a claim, not evidence.

## 3. Unit workflow

```sh
# 0. Only when the tree is stale or configure.py changed. Can trigger a full re-split (minutes) and
#    rewrites the tracked config/RMHE08/symbols.txt with analyzer churn -> check `git status` afterwards.
python configure.py

# 1. Rebuild this unit only (an old .o from different flags can look "matching").
rm -f build/RMHE08/src/<Lib>/<file>.o
ninja build/RMHE08/src/<Lib>/<file>.o

# 2. Authoritative per-symbol numbers for this unit.
build/tools/objdiff-cli.exe diff -p . -u <lib>/<file> --format json -o build/tmp/<file>_diff.json

# 3. Optional: whole-project report (~10 s for 13k units) for unit/section fuzzy percents.
build/tools/objdiff-cli.exe report generate -o build/tmp/report.json

# 4. Raw ELF evidence: section sizes, presence, .comment bytes.
python <skill-dir>/scripts/elfsect.py build/RMHE08/obj/<Lib>/<file>.o build/RMHE08/src/<Lib>/<file>.o
```

Parse the JSON, never print it (it is megabytes):

* `<file>_diff.json` → `d['left']['sections']` (**target**) and `d['right']['sections']` (**ours**); each
  symbol entry has `symbol.name`, `symbol.size`, `match_percent`, `instructions`.
* `report.json` → `units[<unit>].measures` (`fuzzy_match_percent`, `total_code`), `.functions`
  (`name`, `size`, `fuzzy_match_percent`), `.sections`. `report generate` has **no per-unit filter**, so
  find your unit by name in the JSON.

Do **not** verify one unit with `ninja build/RMHE08/ok`: that checks the whole `main.dol` SHA-1, so it
fails (or passes) for reasons unrelated to your unit — and `NonMatching` here means *not linked at all*
(`NonMatching = False` in `configure.py`), so those regions keep original bytes. A red `ok` names no unit.

## 4. Single-function / single-symbol workflow

1. Get the unit diff JSON as above (add the positional `<symbol>` to focus it, if you like).
2. Read that symbol's entry on **both** sides:

   ```python
   for side in ('left', 'right'):           # left = target, right = ours
       for s in d[side]['sections']:
           for x in s['symbols']:
               if x['symbol']['name'] == SYM:
                   print(side, s['name'], x['symbol'].get('size'), x.get('match_percent'))
   ```

3. **Instruction-level diff** (target side entries carry the verdict per instruction):
   `x['instructions'][i]` → `instruction.formatted` (and `original`), `arg_diff`, and on the **left**
   entries `diff_kind`: `None` = identical, otherwise `DIFF_REPLACE`, `DIFF_ARG_MISMATCH`, `DIFF_INSERT`,
   `DIFF_DELETE`. Pair index `i` with the same index on the right side to see what we emitted instead —
   inserts/deletes shift the alignment, so read them in order. Relocated operands (`bl 0x0`, `lis r3, 0x0`)
   legitimately show `0x0` in `formatted`; judge relocations from `.rela.text` / section evidence, not text.
4. Compare sizes first (`symbol.size` on both sides). Equal size + 100 % is a match; a size delta alone is
   already a mismatch, no matter how similar the first instructions look.
5. A symbol present in the target but absent from our object (or vice versa) is a mismatch — check both
   `symbols` lists for the name; if it is missing, look for an inlined or renamed counterpart and report
   which of the two it is.
6. **Data symbols** (tables, vtables, `@etb_*`/`@eti_*`): compare `symbol.size` and then the raw bytes —
   `scripts/elfsect.py` prints section sizes, and its `sections()` helper gives you the byte ranges to
   slice and diff. Section size equal ≠ section content equal.

## 5. Computing the verdict

1. **Sizes first.** Every section present in the target must exist in ours with the *same* size
   (`.text`, `.rodata`, `extab`, `extabindex`, `.sdata*`, `.ctors`/`.dtors`, …). A size difference alone is
   `NOT A MATCH`, whatever the percentages say.
2. **Per-symbol.** Every target function needs `match_percent == 100`. In `report.json`, a function entry
   **without** a `fuzzy_match_percent` key is **0 %**, not 100 % (verified: the unit's
   `fuzzy_match_percent` equals exactly the sum of the *listed* partials over `total_code`).
3. **Cross-check the arithmetic.** `sum(size × match/100) / total_code` must reproduce the unit's
   `fuzzy_match_percent`. If it does not, one of your two readings is wrong — dig in before reporting.
4. **Data content, not just data size.** Byte-diff `.rodata`/`.data`; a single wrong table word is a
   mismatch and the per-symbol percent tells you which table.
5. **Section *presence* is evidence about the flags.** `extab`/`extabindex` (+ `.relaextabindex`) in the
   target but not in ours means the original TU was compiled with C++ exceptions enabled (or as C++) while
   our `cflags` group passes `-Cpp_exceptions off`. Report it as a hypothesis to test on one unit; do not
   "fix" flags in `configure.py` on a hunch (rule 3).
6. **`.comment` identifies the compiler.** `elfsect.py` prints it as hex: `"CodeWarrior"` + a version byte,
   e.g. `0e` (original) vs `0f` (ours). A different version byte means a different code-generation version
   than the one that built the game — a prime root-cause candidate for `0 %` functions, to report (together
   with the `mw_version` in use) rather than paper over.

## 6. Reporting format

Verdict in the first line, then numbers. Say *what* you verified (unit, function, symbol, section):

```md
<unit> / <symbol> does NOT match. Unit code fuzzy match <X>%; <N> of <M> functions at 0%.
.text <ours> vs <target> (<±delta> B); extab/extabindex <present/absent>; .rodata <equal/differs>

| function/symbol | target | ours | Δ | match % |
| --- | ---: | ---: | ---: | ---: |

Evidence: build/tmp/<file>_diff.json, build/tmp/report.json, elfsect.py output (<section> <size> …)
First differing instruction (if symbol-scoped): <addr> `<target insn>` vs `<our insn>` (<diff_kind>)
Root-cause candidates (not yet proven): <flag / compiler / source hypotheses>
```

Never soften it to "essentially matching" / "only sizes differ": a size delta is a mismatch. Never report a
`Matching`-flagged unit as matching without the per-symbol evidence above. A unit is only "matching" when
*all* its symbols are 100 % and every section size matches.

## 7. Guardrails

* Nothing is committed or pushed without explicit user approval (rule 6); leave results in the working tree
  and state exactly what you would commit.
* Do not edit `configure.py` flags/`mw_version`/tool versions to force a match (rule 3), and do not flip
  `Object(Matching, …)` in either direction as a "fix" — report and ask.
* Never print `config/RMHE08/symbols.txt` (rule 7): grep or slice it.
* Save findings (numbers + repro commands) to `build/tmp/<name>-verification.md`, so the conclusion survives
  even if the tree is later cleaned.

## 8. Worked example — `main/Camellia/camellia` (2026-09-20)

objdiff-cli 2.7.1, `python configure.py` freshly re-split, unit rebuilt. Result: **NOT a match**, unit
`fuzzy_match_percent` 1.4876565 while `complete_code_percent` read 100.0.

| function | target | ours | Δ | match % |
| --- | ---: | ---: | ---: | ---: |
| `camellia_setup128` | 3308 | 3252 | −56 | 0.00 |
| `camellia_setup256` | 4860 | 4748 | −112 | 0.00 |
| `camellia_setup192` | 168 | 168 | 0 | 45.24 |
| `camellia_encrypt128` | 3228 | 2628 | −600 | 0.00 |
| `camellia_decrypt128` | 3228 | 2628 | −600 | 0.00 |
| `camellia_encrypt256` | 4284 | 3492 | −792 | 0.00 |
| `camellia_decrypt256` | 4284 | 3492 | −792 | 0.00 |
| `Camellia_Ekeygen` | 68 | 224 | +156 | 10.71 |
| `Camellia_EncryptBlock` | 496 | 448 | −48 | 28.23 |
| `Camellia_DecryptBlock` | 496 | 448 | −48 | 28.23 |
| **`.text`** | **24420 (0x5F64)** | **21600 (0x5460)** | **−2820** | **1.49** |

* `.rodata` size equal (4096) but `camellia_sp3033` only 99.61089 % (≈4 bytes differ).
* target has `extab` 72 B (9 × `@etb_*`), `extabindex` 108 B, `.relaextabindex` 216 B; ours has none.
* `.comment`: target `…6f72 0e 04 00 00 01 01 02 00 16 2c…`, ours `…6f72 0f 04 …` → version byte **0x0E vs
  0x0F**; `config.yml` says `mw_comment_version: 14`, matching the original.
* Sum check: `(496·0.2823·2 + 168·0.4524 + 68·0.1071) / 24420 = 1.487 %` ✔ reproduces the unit number.
* Symbol-scoped example: `camellia_setup192` (equal size, 45.24 %) — first divergence is instruction 2,
  target `stw r0, 0x44(r1)` vs ours `li r5, 0x18` (`DIFF_REPLACE`), i.e. our prologue/register allocation
  differs from the start.
* Open hypotheses (unproven): the `Wii/1.3` compiler from the 20251118 package (reported as `mwcc_43_172`)
  is a different codegen version than the original; and/or this TU needs C++ exceptions on.
  Full write-up: `build/tmp/camellia-verification.md`.

## 9. scripts/elfsect.py

Minimal dependency-free ELF section dumper (PPC32 big-endian objects); importable for byte-level work:

```sh
python scripts/elfsect.py <obj> [<obj> ...]   # name / type / size / addr, plus .comment hex bytes
```

```python
import sys; sys.path.insert(0, "<skill-dir>/scripts")
from elfsect import sections          # -> (raw_bytes, [ {name, typ, addr, offset, size, data}, … ])
```
